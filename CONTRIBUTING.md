# Работа с проектом

## Подготовка

Создайте окружение по README и установите `requirements-dev.txt`.
Настройки окружения описаны в `.env.example`; локальный `.env` не хранится в Git.

## Структура изменений

- Добавляйте сценарии в `tests/<область>/`, подготовку данных — в `fixtures/`.
- Храните статические тестовые файлы в `testdata/`, общие инструменты — в `tools/`.
- Размещайте HTTP-запросы и Pydantic-модели в `clients/`, повторяющиеся проверки — в `tools/assertions/`.
- Каждый тест должен работать отдельно и не зависеть от порядка запуска.
- Регистрируйте новые маркеры в `pytest.ini` и обновляйте README при изменении сценариев или команд запуска.
- Используйте вымышленные данные. Не коммитьте реальные пароли, токены, состояние сессий и отчёты.

## Проверка

Все команды выполняются из корня репозитория:

```bash
python -m ruff check .
python -m ruff format --check .
python -m pytest --collect-only -q
python -m pytest -m regression -n 2 --alluredir=allure-results
```

Для регрессии нужен отдельный тестовый API-сервер по инструкции в README.

## Pull request

Опишите изменившееся поведение, выполненные команды и результаты проверок.
Если часть проверок недоступна, укажите причину.
Изменения форматирования выполняйте через `python -m ruff format .`.
